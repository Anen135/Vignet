# Установка и локальный запуск Vignet

## Интерактивное меню

Из папки проекта запустите `npm run setup` (или `npm run menu`). Выберите **1 — Настроить всё**: меню установит отсутствующие зависимости, соберёт расширение и найдёт `cloudflared` в папке проекта, распакованном каталоге клиента или PATH. Если файл находится в другом месте, укажите путь к `cloudflared.exe`. Скачать клиент: [Cloudflare Downloads](https://developers.cloudflare.com/tunnel/downloads/).

Затем выберите **2 — Запустить Bridge и туннель** и оставьте терминал открытым. Меню запускает HTTP Bridge и выбранный агент (Cloudflare Quick Tunnel или ngrok), показывает публичный MCP URL и проверяет, что он ведёт именно к этому процессу Bridge. Ключи OpenAI не требуются; для Quick Tunnel не требуется и аккаунт Cloudflare. Прямой запуск ngrok — `npm run start:ngrok`, Cloudflare/сохранённого режима — `npm run start:cloudflare`. Ctrl+C останавливает принадлежащие launcher процессы; существующий внешний туннель не останавливается.

Загрузите `dist/extension` в браузер и в ChatGPT добавьте custom MCP server с **Connection: Server URL**, показанным HTTPS адресом с `/mcp` и **OAuth**. Поля Client ID / Secret оставьте пустыми для автоматической регистрации. На странице подключения появится код: сравните его с кодом в терминале Vignet и подтвердите запрос словом «да». Пароль и OpenAI API key для этого не нужны. По умолчанию доступ отклоняется; запрос истекает через 45 секунд. Публичный адрес не даёт доступ к инструментам без авторизации.

Пункт **3** проверяет уже работающие Bridge, туннель и обязательность OAuth. Для проверки из второго терминала откройте ещё одно меню, не запуская второй Bridge. Пункт **6** показывает настройки расширения. Существующий `deviceToken` сохраняется. Настройки находятся в `%LOCALAPPDATA%/Vignet/cloudflare.json` (или каталоге пользовательских настроек Vignet на других ОС), регистрации одобренных OAuth-клиентов — в `oauth-clients.json`. Access/refresh tokens хранятся в памяти: после перезапуска Bridge потребуется повторная авторизация. Старые `setup.json` и профили OpenAI не используются.

`npm run start:private` и `npm start` одновременно с launcher запускать не нужно. Если порт занят, меню попросит остановить прежний процесс. Установка расширения и добавление плагина выполняются вручную в интерфейсе браузера и ChatGPT.

## Адрес туннеля и альтернативы

[Cloudflare Quick Tunnel](https://developers.cloudflare.com/tunnel/get-started/quick-tunnels/) выдаёт случайный временный адрес `trycloudflare.com`. Закрепить или восстановить `https://prevention-highways-algorithm-ing.trycloudflare.com/mcp` нельзя. Если старый туннель ещё запущен, выберите **5 → режим 2**, оставьте этот адрес и направьте его origin на `http://127.0.0.1:8789`. Launcher проверит совпадение Bridge, прежде чем считать подключение готовым. Quick Tunnel не поддерживает SSE; наш HTTP MCP отвечает JSON и не требует SSE.

Тот же **режим 2** поддерживает уже работающий HTTPS туннель другого провайдера. Он запускает только защищённый Bridge и не меняет настройки внешнего туннеля:

| Вариант | Адрес | Начальная настройка |
| --- | --- | --- |
| Cloudflare Quick Tunnel | Новый после перезапуска | Меню автоматически запускает `cloudflared` |
| Cloudflare Tunnel со своим доменом | Постоянный | Аккаунт Cloudflare, домен и настроенный tunnel |
| Tailscale Funnel | Стабильный `*.ts.net` | Установить Tailscale, войти в аккаунт, включить Funnel и HTTPS |
| ngrok | Закреплённый dev domain бесплатного аккаунта | Установить ngrok, настроить authtoken; меню **5 → режим 3** запускает его автоматически |

Для [Tailscale Funnel](https://tailscale.com/docs/reference/tailscale-cli/funnel), после настройки аккаунта, запустите в отдельном терминале:

```powershell
tailscale funnel 8789
```

Для автоматического запуска [ngrok](https://ngrok.com/download/windows) установите клиент и один раз настройте authtoken аккаунта по официальной инструкции. Launcher использует стандартную конфигурацию ngrok или переменную `NGROK_AUTHTOKEN`; токен не передаётся в аргументах запуска и не сохраняется в настройках Vignet. В меню выберите **5 → режим 3**, оставьте команду `ngrok` или укажите путь к `ngrok.exe`, затем введите постоянный dev domain из [ngrok Dashboard → Domains](https://dashboard.ngrok.com/domains). Сохраните настройки и выберите **2**. Установка через Microsoft Store (`winget install ngrok -s msstore`) поддерживается: меню проверяет `ngrok version`, не требуя доступа к защищённому файлу WindowsApps через stat/access. После установки откройте терминал заново, чтобы обновился PATH. Адрес определяется по сообщениям агента или через его локальный API `http://127.0.0.1:4040/api/endpoints`; копировать URL из отдельного терминала не нужно. Если в ngrok изменён порт `web_addr`, задайте соответствующий `VIGNETTE_NGROK_API_PORT` перед запуском меню. Прямой запуск с сохранённой командой/путём или `NGROK_PATH`:

```powershell
npm run start:ngrok
```

Домен хранится отдельно от последнего обнаруженного URL в поле `ngrokDomain` файла `cloudflare.json`. Запуск всегда передаёт `--url https://<dev-domain>` и проверяет совпадение фактического адреса. Без настроенного домена запуск останавливается с инструкцией; случайный адрес из предыдущего лога не используется автоматически. Для ручного запуска также поддерживается `VIGNETTE_NGROK_DOMAIN`. Домен должен принадлежать вашему ngrok-аккаунту: простое сохранение случайного URL не резервирует его.

Если authtoken отсутствует или отклонён, меню покажет код `ERR_NGROK_*` и остановит Bridge. HTTP-инспекция ngrok отключена флагом `--inspect=false`. В ChatGPT по-прежнему используется OAuth Vignet с локальным подтверждением. Не выбирайте No authentication.

Внешний ngrok можно также запустить вручную и использовать через **режим 2**:

```powershell
ngrok http 8789
```

Для внешнего туннеля скопируйте показанный HTTPS адрес, добавьте `/mcp` и сохраните в **5 → режим 2**. Затем запустите Bridge пунктом **2**. На бесплатном ngrok действуют квоты (20 000 HTTP-запросов и 1 ГБ исходящего трафика в месяц); браузер может показать промежуточную страницу перед OAuth — пройдите её вручную. Ни один туннель сам по себе не заменяет авторизацию MCP. Управляемый запуск встроен для Cloudflare и ngrok; Tailscale запускается отдельно. Реальная сеть проверена для Cloudflare; ngrok проверен тестовым процессом без подключения аккаунта.

## Сборка и пакеты

Требуются Node.js 20+ и Chromium 135+ для запуска Asset с JavaScript. Из корня репозитория:

```powershell
npm install
npm run check
npm test
npm run build
```

Загрузите в `chrome://extensions` → «Режим разработчика» → «Загрузить распакованное расширение» каталог `dist/extension`. В карточке расширения включите **Allow User Scripts**, если требуется запуск JS Asset. Примеры пакетов создаются в `dist/packages/`; их можно собрать отдельно командой `npm run pack:asset -- packages/rain dist/packages/rain.vignet`.

Откройте `https://chatgpt.com/`, обновите вкладку и нажмите иконку Vignet, чтобы открыть каталог. Выберите `.vignet`, проверьте манифест, действия, автора и разрешения, установите явным подтверждением, затем запустите действие из карточки с выбранной вкладкой и областью. Установка не запускает Asset автоматически. CSS-тема не требует Allow User Scripts.

## MCP и Bridge

HTTP endpoint остаётся на `http://127.0.0.1:8789/mcp`; WebSocket расширения — `ws://127.0.0.1:8788/extension`. Рекомендуемый запуск создаёт credentials владельца вне проекта и автоматически передаёт их HTTP Bridge:

```powershell
npm run start:private
```

Launcher создаёт `%LOCALAPPDATA%/Vignet/credentials.json` на Windows (или `$XDG_CONFIG_HOME/Vignet/credentials.json` / `~/.config/Vignet/credentials.json` на других системах). Он не выводит значения ключей. Возьмите `apiToken` из этого файла и укажите его MCP-клиенту как `Authorization: Bearer <apiToken>`. Откройте настройки расширения Vignet и задайте `deviceToken` из того же файла. Защитите credentials-файл и не помещайте его в репозиторий.

Для ручного запуска задайте `VIGNETTE_API_TOKEN` и `VIGNETTE_DEVICE_TOKEN` в окружении перед `npm run start:http`. Не публикуйте туннель без API token.

```powershell
$env:VIGNETTE_API_TOKEN = '<apiToken>'
$env:VIGNETTE_DEVICE_TOKEN = '<deviceToken>'
npm run start:http
```

HTTP-адаптер запускает stdio MCP Bridge как дочерний процесс. Для отдельного stdio Inspector используйте `npm start`; не запускайте одновременно два процесса Bridge на WebSocket порту `8788`. При подключении HTTP MCP-клиента укажите endpoint и bearer token в его настройках. Расширение должно получить токен устройства в разделе соединения.

Если порт отличается, задайте `VIGNETTE_HTTP_PORT` или `VIGNETTE_PORT`. Внешние endpoint для расширения должны использовать `wss://`; незашифрованный `ws://` разрешён только loopback адресам.

## Ручная проверка Chromium/ChatGPT

`npm run test:browser` собирает расширение и запускает автоматический Playwright сценарий на синтетической странице ChatGPT; он не проверяет подключённый аккаунт или настоящий сайт. После установки расширения:

1. Убедитесь, что диагностический раздел показывает подключённый Bridge и открытую вкладку ChatGPT.
2. Импортируйте `rain.vignet`, проверьте карточку и явно предоставьте разрешения `user_scripts`, `dom_access` и `audio`; запустите дождь в выбранном чате без звука.
3. Перейдите в другую беседу: Rain должен остановиться; вернитесь в исходную — конфигурация должна восстановиться. Проверьте также новую временную беседу и две открытые вкладки.
4. Обновите интенсивность, остановите и снова запустите Rain; проверьте, что капли и медиа URL очищаются.
5. Проверьте legacy MCP `set_vignette` и `get_vignette_status`, затем универсальные `list_assets`, `describe_asset`, `run_asset`, `update_asset_instance`, `stop_asset`, `list_asset_instances`, `get_contexts`, `get_asset_status`.
6. Для звука нажмите/кликните страницу при заблокированном autoplay и повторите запуск звукового действия. Отдельно проверьте обновление вкладки, отключение/возврат Bridge и экспорт/повторный импорт пакета.

Автоматический браузерный сценарий проверяет настоящее исполнение `userScripts.execute`, Allow User Scripts, UI, IndexedDB, переходы A/B и восстановление на синтетической странице в изолированном Chromium. Для первого запуска установите браузер: `npx playwright install chromium`. Автозапуск звука, UI текущего сайта ChatGPT, настоящий аккаунт и MCP-плагин требуют отдельной ручной проверки.
