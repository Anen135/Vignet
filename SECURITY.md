# Безопасность и границы доверия

Vignet — локальная система для одного владельца установки. Её нельзя считать многопользовательским SaaS: отдельные пользователи должны иметь собственные изолированные установки, базы данных и credentials. `Origin` помогает ограничить локальный WebSocket, но не является аутентификацией.

## Сеть и credentials

- WebSocket расширения слушает loopback `127.0.0.1:8788` и проверяет `chrome-extension://` Origin. `VIGNETTE_EXTENSION_ID` позволяет закрепить ожидаемый ID.
- HTTP-адаптер обслуживает JSON MCP на `127.0.0.1:8789/mcp`. Запуск `npm run start:private` создаёт случайные credentials для владельца вне репозитория: `%LOCALAPPDATA%/Vignet/credentials.json` (Windows) или `$XDG_CONFIG_HOME/Vignet/credentials.json` / `~/.config/Vignet/credentials.json` (другие системы). Файл содержит `apiToken` для MCP Bearer и `deviceToken` для связи расширения; значения не печатаются в терминал. Запросы требуют `VIGNETTE_API_TOKEN` и `Authorization: Bearer <token>`; этот launcher задаёт переменную из файла. `/health` предназначен для локальной диагностики.
- Расширение идентифицирует установку device ID и проверяет device credential `VIGNETTE_DEVICE_TOKEN`. Токен вводится в настройках подключения и хранится в пользовательских настройках браузера. В текущей модели один credential обслуживает один deployment; это не изоляция множества пользователей.
- Храните секреты в окружении процесса или локальном менеджере секретов. Не включайте их в Git, ZIP Asset, логи или URL.
- Публичный запуск `npm run start:cloudflare` включает OAuth и сохраняет локальный owner bearer token. Доступ без токена отклоняется с `401` и OAuth discovery. `cloudflared` проксирует только HTTP порт 8789; WebSocket расширения остаётся локальным. Публичный URL сам по себе не даёт доступ к MCP. Не публикуйте обычный HTTP-адаптер без owner bearer credential или OAuth.

## OAuth публичного MCP

Launcher не использует OpenAI API key. OAuth-клиент регистрируется динамически; redirect разрешён только на HTTPS `chatgpt.com`, `chat.openai.com` или HTTP loopback для локального Inspector. Каждый запрос требует PKCE S256 и точного resource `${publicOrigin}/mcp`. Публичный Origin задан launcher и не выводится из входящих Host/X-Forwarded заголовков. OAuth-метаданные и страница подключения доступны публично; инструменты защищены.

Разрешить доступ может только владелец в локальном терминале: браузер и терминал показывают один случайный код для сверки. Решение передаётся Bridge через Node IPC; публичного endpoint для одобрения нет. Запрос истекает через 45 секунд, при отсутствии интерактивного терминала доступ отклоняется. Подтверждайте только код собственной страницы подключения. Регистрации не подтверждают идентичность клиента сами по себе.

Коды авторизации одноразовые и живут 60 секунд. Access tokens живут час, refresh tokens — сутки и меняются при использовании; повторное использование старого refresh token отзывает активную семью токенов. В памяти хранятся хеши токенов. Одобренные регистрации клиентов и хеши client secrets сохраняются вне проекта в `oauth-clients.json`; access/refresh tokens не записываются на диск. После перезапуска Bridge нужна повторная авторизация. Количество регистраций, запросов согласия и токенов ограничено; публичные OAuth endpoints имеют лимит запросов. Это ограниченная реализация для одного владельца, не полноценный многопользовательский identity provider.

Launcher проверяет публичный `/health` по случайному идентификатору текущего Bridge, не передавая owner credential чужому URL. `/health` раскрывает только готовность и идентификатор процесса подключения. Cloudflare, Tailscale Funnel и ngrok остаются публичными прокси; защита MCP не должна зависеть от непредсказуемости URL.

Управляемый ngrok использует authtoken из своей конфигурации или `NGROK_AUTHTOKEN`. Vignet не записывает его в свои настройки и не передаёт через CLI-аргументы. Owner/device credentials Bridge не передаются процессу туннеля; ngrok authtoken не передаётся в Bridge. HTTP-инспекция ngrok отключена. Launcher принимает HTTPS URL из сообщения запуска агента и проверяет связь с собственным Bridge; при ошибке агента Bridge останавливается. OAuth и локальное подтверждение остаются обязательными для публичного доступа.

Рекомендуемый запуск — `npm run start:private`: он использует сохранённые credentials и запускает HTTP Bridge. Альтернатива `npm run start:http` для ручной конфигурации требует задать оба токена окружения. При отсутствии `VIGNETTE_API_TOKEN` адаптер разрешает только loopback Host и отклоняет запрос с заголовками, указывающими на внешний proxy. Не устанавливайте обратный proxy, который убирает эти заголовки и превращает endpoint в публичный открытый доступ.

## Пакеты и исполняемый код

Установка проверяет ZIP directory/local headers, CRC, пределы размера и сжатия, traversal, дубликаты, манифест, объявленные файлы, MIME и SHA-256. Инсталлятор не исполняет код во время импорта. Пользователь должен подтвердить установку и каждое заявленное разрешение. Медиа хранится локально в IndexedDB по content hash; одинаковые данные разделяются, сборщик мусора удаляет только неиспользуемые записи.

Пакетный JS запускается через `chrome.userScripts` в `USER_SCRIPT` isolated world. Требуются современный Chromium (135+) и включённое пользователем **Allow User Scripts**. Небезопасный `MAIN` world не поддерживается. Изолированный мир ограничивает доступ к внутренностям расширения, но **не защищает приватность DOM страницы**: такой скрипт способен читать текст открытого чата. Разрешайте JS только пакетам, которым доверяете, после чтения автора, действий и разрешений.

Для полностью недоверенного пользовательского кода предпочтителен sandboxed iframe с ограниченным message API; такой режим в текущей версии не реализован. Cleanup API управляет таймерами, событиями, observers, DOM-узлами, audio и Blob URL. Произвольные monkey-patches, глобальные изменения страницы и побочные эффекты нельзя гарантированно отменить; пакет может объявить `cleanupGuarantee: "best-effort"` и `requiresReloadOnStop: true`.

`dom_overlay` разрешает управляемый визуальный слой, `dom_access` явно отмечает доступ к DOM, `user_scripts` — исполнение пользовательского JS, `audio` — локальное воспроизведение звука. Бинарные данные не передаются через MCP/WebSocket; импорт происходит локально в UI.

## Контексты и маршрутизация

Когда доступно несколько вкладок ChatGPT, действие требует однозначного `target.tabId`; Bridge не выбирает случайный WebSocket и не рассылает команду по всем устройствам. `get_contexts` возвращает открытые контексты, включая временные чаты без ID. ID берётся из URL, содержимое беседы не читается для идентификации. HTTP RPC обрабатывает только небольшой JSON; медиа следует устанавливать через локальный UI.

Публичные вызовы MCP ограничены объёмом WebSocket-сообщения. `received` означает только приём команды; успешное применение подтверждается отдельным `applied` ответом.
